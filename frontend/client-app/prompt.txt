Develop a **single professional Agrivet mobile application** using **React Native + TypeScript + NativeWind (Tailwind CSS)** with a **shadcn/ui-inspired reusable component system**.

The application must support **two roles in one mobile app**:

* **AGENT**
* **BRANCH**

The system must detect the authenticated user's role and display only the appropriate features, navigation, data, and actions for that role.

The application should be **feature-based, scalable, secure, minimalist, and production-ready**.

---

Create a **My Customers** module for Agents.

# 9. UNIFIED APPROVAL AND ASSIGNMENT WORKFLOW

Both **Customer Bookings** and **Branch Orders** must use the same approval and assignment process.

## Stage 1 — Pending

The Agent or Branch submits the transaction.

```text
PENDING
```

It is now available to the **Super Admin / Booking Admin**.

## Stage 2 — Accept or Reject

Super Admin / Booking Admin can:

```text
[ Accept ]
[ Reject ]
```

If rejected:

```text
PENDING → REJECTED
```

If accepted:

```text
PENDING → ACCEPTED
```

Then show:

```text
[ Assign to Admin ]
```

## Stage 3 — Assign Admin

Super Admin / Booking Admin selects an Admin.

```text
Select Admin
     ↓
Confirm Assignment
     ↓
ASSIGNED
```

Save the assigned Admin ID in the database.

## Stage 4 — Assigned Admin

The assigned Admin receives the transaction in their **My Assigned Bookings / My Assigned Orders** module.

The assigned Admin can:

```text
ASSIGNED
    ↓
Accept
    ↓
ACCEPTED
    ↓
Processing
    ↓
PROCESSING
    ↓
Ready
    ↓
READY
    ↓
Completed
    ↓
COMPLETED
```

Only the assigned Admin can perform these processing actions.

# 18. SECURITY AND DATA ISOLATION

Do not rely only on frontend filtering.

The backend must enforce ownership and permissions.

### Agent

Every customer query must be scoped to:

```text
customer.agent_id = currentUser.id
```

Every Agent booking query must be scoped to:

```text
booking.agent_id = currentUser.id
```

### Branch

Every Branch order query must be scoped to:

```text
order.branch_id = currentUser.id
```

or the appropriate Branch relationship in the existing database.

Users must not gain access to another user's data by manually changing an ID in an API request.

Backend authorization must enforce all role permissions.

---

# 19. IMPORTANT BUSINESS RULES

Keep these concepts completely separate:

```text
CUSTOMER BOOKING
Agent → Customer → Product → Booking
```

and:

```text
BRANCH ORDER
Branch → Product → Order
```

A Customer Booking:

* Does not require a Branch.
* Is created by an Agent.
* Belongs to the Agent who created it.
* Is for a specific Customer.

A Branch Order:

* Does not require a Customer.
* Is created by a Branch.
* Belongs to the Branch that created it.
* Is used for Branch inventory ordering.

Both use the same:

**Pending → Accept/Reject → Assign → Admin Processing → Ready → Completed**

workflow.
